# 冻结 M2/M3 的平衡条件对照

**得到一条在新私有条件上保留完整多目标收益的M3候选，尚不能判断M3普遍优于M2。** 八逻辑任务中六个完成，两条首请求服务过载不属于冻结的429重试规则；只剩两条完整配对。最终有效改进M2为0/4、M3为1/4，缺失与算法质量分开报告，不生成M4或补跑。

从 fbb6c0b 出发，先完成两阶段准备，再于 **d3acdad** 冻结代码和门槛后启动真实提案。两阶段证据见 [PREPARATION.md](PREPARATION.md)，预注册细节见 [PROTOCOL.md](PROTOCOL.md)。本轮没有修改 M2/M3、原生 Codex Backend、任务生成器、MeshWorld、Verifier、资产或原多目标验收规则，没有 M4、GPU、渲染或训练。

## 准备与实验范围

dev、selection、新私有test各24个条件，四族各6，每条件4个共享随机种子；三划分360个任务/算法seed无重合。两份新初始程序和全部策略/重复共享条件池。初始算法在测量前提交：axis_target沿x轴进行水平目标投影，elite_centroid在初期采样后向精英位姿均值附近收缩；没有根据分数修起点。

首次72条件原型中1个doorway参考重复mesh_passage失败，因此在任何初始算法测量/模型调用前停止并保留原型。准备规则修订先提交为a616dd2：仅接收原参考通过原评价器的条件，三划分统一、失败单列，最多128次生成取得72个条件；不修参考、任务或评分，也不看生成器成绩。最终新池72次直接全部通过，没有条件级补抽。结论限于参考可验收条件，不能把提供的参考失败等同任务无解或声称构造器永不出错。

阶段1共384次初始算法dev/selection生成，均零运行错误、24查询；Axis硬成功92/96、94/96，Elite均96/96。私有test算法成绩直到全部selection决定保存后才计算。模型原始反馈池各96条；沿用冻结策略及原MENU自主选恰好8例，重复间任务JSON相同，两策略统计池相同。MENU仍仅提供开发索引0..5的Probe，余下条件进入共同统计；本轮未替策略扩大Probe访问范围。

## 固定调度与服务缺失

8个逻辑任务全部按预注册顺序尝试，K=1、Codex并发1。两次服务容量失败分别为 Elite/M3/r0 和 Axis/M2/r1，其余6个完成原生编辑、静态审计和后续隔离评价。没有补选或追加逻辑任务。

本轮**没有HTTP429**，因此实际重试次数和等待时间均为0。两次失败首请求HTTP200，但SSE包含 `error` / `response.failed`：`type=service_unavailable_error`、`code=server_is_overloaded`、`Our servers are currently overloaded. Please try again later.`；Retry-After分别327/320秒。CLI转述为 `Selected model is at capacity. Please try a different model.`，无usage、无Diff。

它们不满足冻结的“首请求HTTP429、未产生修改/模型输出”的重试条件。本轮未中途扩展错误类别、改模型、等待更久再重打或把过载当代码失败。降低并发并未消除服务过载；不能由HTTP200推断模型成功，`model_calls.status=completed`仅表示响应流接收结束。原始CLI/SSE及报告中的 `failed_attempt_details` 保留确切错误码。

## 研究结论与复现

可以确认：M3产生了一条已由平衡验证接受、并在新的私有条件上保持质量/多样性/可见性/硬成功的生成算法修改。收益发生在相同24查询下，来自位姿生成/修复逻辑，不是增加可解性拒绝采样预算、改资产/相机或改评分。

不能确认：M3普遍优于M2、收益来自元策略的哪个单独机制，或已证明递归能力提升。只有2条完整配对且缺失非随机地改变起点构成；本轮无元策略消融，不能把局部修复程序的一次成功当元级因果证明。在更大且平衡的数据上，这条具体候选获得稳定经验支持；没有样本量消融，不能把稳定性归因于扩大数据本身，服务缺失和部分跨划分差异也仍存在。

本轮不生成M4、不补跑两缺失槽位。若开展下一轮，需在新预注册中明确处理HTTP200的 `response.failed/server_is_overloaded`，以及其320余秒Retry-After与600秒逻辑总时限的关系，不能把现有30/60秒429规则临时套用。仍须保留累计预算和完全相同的策略/工具权限。
