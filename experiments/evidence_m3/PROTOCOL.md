# 证据驱动 M2 → M3：运行前协议

基于 bfa608e。一次策略原生编辑，资格失败立即停止，不人工修补、不追加候选、不生成 M4。冻结 M2、MeshWorld、资产/任务定义、原 eligible、Coding Backend 和受限执行器。研究方向由用户/研究者指定，不能把全部方法发现归于父代自主涌现。

先固定两个新初始程序：coordinate_walk 为单坐标随机局部步进；whole_restart 为整布局重启。二者复用旧参数化和输出合约，但更新机制不同。它们在 M3 编辑前提交，不提供给策略编辑器。M3 冻结后才生成新的场景条件和算法种子，不复用旧盲测。

共同适配不改 M2：输入为 current/history/constraints，输出仍沿用 choose/propose；M3 可附 diagnosis。由策略自己给出 objective、observed/hypothesis/unknown、可解析证据字段路径、probe 和预期观测。控制器只验证与原样转发，不补诊断或 Probe 例子。Coding Backend 的公共边界仍为 task → patch。

资格检查：对 runtime、硬成功、位置、旋转、可见性、偏好六种当前违反项，各替换三种历史风险。observed 诊断须保持与当前事实相符，引用实际 current 数值；改变当前违反项须改变诊断，且 probe 或交付示例成员集合至少一项改变。仅历史风险的包不得宣称当前相对保持率退化已 observed。每个正式 propose 必须由 M3 自己选到至少一个所选 Probe 条件的完整四种子组，最多八例；记录实际 TASK 交付，不能以文本/重排序或 controller 补齐充数。

每初始程序独立新 dev 6、selection 6、私有 test 12 条件，各四个共享种子。原四种 Mesh 场景族轮换，不扩展场景类型，合法参考状态只由可信评价器验证，不交给策略或后端。若任一参考非法或预登记 dev 可行性不足（无运行错误、硬成功至少50%、偏好误差至少.02m、位置多样性>.05m），停止，不重采样或修改初始程序。

共同 dev 已测池每条件四次。choose 先见共同条件0/1的汇总及全池基线多目标指标；菜单 random=(2,3)、dense=(3,4)、barriers=(4,5)。propose 得到共同8例+所选Probe8例，选择最多8例。Probe是对固定已测池的反馈选择，不新增 Mesh 查询。M2/M3收到相同字段、菜单、历史和固定约束；允许策略输出导致反馈选择不同。M2丢掉Probe或选不完整组照实记录，不替它修复，不对M2追加新资格要求。

四种子多样性：每条件六个种子对沿用原 distance，再跨条件平均；合法配对仅计两个输出都硬成功的种子对，合并原有效配对距离，记录总配对数。原双种子测量有样本数改变，不能与旧报告数值直接混算。每次生成仍24查询，原独立最终物理/通行评分不变。

原 eligible 固定：硬成功不下降、无运行错误、平均可见性损失≤.01、全配对和合法配对位置均保持≥90%、旋转保持≥80%、合法配对数不下降、偏好误差改善≥.01m。只用selection决定接受/回退。四个K=1提案全部封闭、selection记录保存后，才评分新私有test；原始候选和回退版本分别报告，不用test补选。

最多5个真实编码任务（M3创建1 + 两初始程序×M2/M3各1）；同gpt-6.1-sol medium、CLI和原生工具、600秒、6服务请求、每请求4096输出Token、累计400000Token、原输入/资源上限。每个任务在调用前预留，失败消耗配额，不隐式重启。服务请求数与编码任务数分开，M3创建成本单列，无模型采样追加。无GPU或渲染。

主要观察新机制是否真实执行、独立选择接受率、采用后偏好收益及终测全部多目标约束。报告原始候选的硬成功、位置/旋转多样性、可见性、偏好、时间和Token。每策略仅2个初始程序、各一次模型样本，只能给小规模可行性证据，不能作稳定元能力或持续RSI结论。
