## 独立泛化结果

12 组各 16 张地图，共 192 张；150 张存在合法可解任务，42 张经穷尽原始
状态转移图证明不存在符合最小距离规则的可解任务。正例还由原 BFS 独立
检查存在性见证；这些见证保存在服务器私有运行目录，没有提供给任何提案。
地图含新尺寸组合、14.3%–75% 障碍密度、门洞、交叉墙、交错通道、分离
区域及横杆。仍遵守原系统每边 4..8 格的范围，没有扩大物理或任务语义。

两种算法处理同一地图、同一输入排列，只生成一次，`require_solvable=False`，
没有重新采样输出，也不使用搜索器筛掉失败输出。输入中的初始随机角色满足
原有几何最小距离；这不同于旧基准按完整原始采样流反复拒绝的分布。

完整逐场景数据与汇总在 [results/blind](results/blind)。

## Meta-Agent 的可修改边界

原始程序为 `scene_rsi/agent/meta_policy.py`，不会在宿主 Python 中导入。
同一 `layout(packet)` 数据接口接收两种阶段：

- `choose`：根据 8 张公共 dev 地图指标选择 random/barriers/dense 中一个 16 张探测集。
- `propose`：分析 24 张 dev 反馈，选最多 8 个样例，输出分析文本和提案指令。

Codex 使用一个训练生成器的优化轨迹，自动产生下一代策略源代码；下一代程序
可以改变上述三种机制。真实提案完整源代码、理由、Diff、静态审计、策略输入输出、
隔离执行指标及调用成本全部归档。没有人工逐轮修改或筛选源代码。

外部 `scripts/run_metaimp.py` 固定模型、K=1、总调用数≤6、输出 Token≤8192、
每次调用≤180 秒以及独立 dev/val 评分和选择。策略既不能改变这些项目，也不能
选择 val 作为开发实验。候选生成器仍只改变自己的一个源文件；可信评价器不在
候选挂载中。最终选择只允许几何有效、物理重放通过且 val 可解数严格增加的候选。

固定地图池先由独立存在性检查选取可行地图，双方使用同一池与相同数量；这属于
基准构建，不是对生成场景进行可解性拒绝采样。每个候选每张地图仍只有一次输出。
两个保留初始生成器是事先编写并冻结的 `initial_edge.py` 和 `initial_spread.py`，
在元策略冻结后才提供给两种策略；它们不是足以代表一般程序分布的大样本。

MetaImp@1 定义为选中版本相对初始版本的 val 可解率增量，再对两个初始生成器
取平均。不同策略在保留阶段预算相同；生成新策略额外花费的一次训练优化和一次
策略提案单列，不把这项成本抹去。具体结果见 [results/meta/summary.json](results/meta/summary.json)。

### 实际最小对照

共六次真实 Codex CLI 调用，六次上游 HTTP 200，模型均为 `gpt-6.1-sol`；没有
传输重试或人工候选修订。一次训练优化、一次元程序修改，随后是两个初始生成器
× 两种元策略 × K=1。训练生成器在 dev 上由 4/24 提升至 24/24；训练不使用 val。

| 初始生成器 / 元策略 | 初始 dev | 候选 dev | 初始 val | 候选 val | 选中版本 val |
|---|---:|---:|---:|---:|---:|
| edge / 原策略 | 1/24 | 24/24 | 0/24 | 24/24 | 24/24 |
| edge / 修改后策略 | 1/24 | 24/24 | 0/24 | 24/24 | 24/24 |
| spread / 原策略 | 12/24 | 未执行 | 9/24 | 未执行 | 9/24 |
| spread / 修改后策略 | 12/24 | 24/24 | 9/24 | 24/24 | 24/24 |

原策略 MetaImp@1 为 **0.50**，修改后为 **0.8125**，差 **+0.3125**。
这次差异**全部来自 spread 原策略候选被既有 AST 规则拒绝**：它在第 53 行使用
函数内 `nonlocal best_key, best`。固定审计拒绝所有 Global/Nonlocal；这是一条
保守语法规则，不能据此推断该局部变量存在恶意行为，也不能推断其场景生成质量。
没有放宽规则、手改候选或执行被拒代码。其余三个保留候选的 dev/val 均为 24/24，
原物理环境成功重放所有求解结果。

因此，这提供一次自动元程序修订和全流程合规效率差异的实测；**没有证明修改后的
元策略能提出更强的场景算法**。两个初始程序、每组一次随机模型采样也不足以排除
采样运气。四个保留优化实际上都选择 random 探测；可修改的实验选择机制已经
执行，但本轮没有观察到不同实验选择的收益。修改后程序主要增加跨尺寸/密度及
成败类别的样例覆盖，并生成更具体、更长的算法研究指令。原生产默认元策略保持
简短的初始程序；生成的新程序仅作为冻结的实验候选保留。

| 成本 | 原策略保留阶段 | 修改后保留阶段 | 额外训练与元修订 |
|---|---:|---:|---:|
| 模型调用 | 2 | 2 | 2 |
| 实际 Token 总量 | 28,987 | 33,157 | 32,951 |
| 提案 CLI 墙钟总时间 | 187.65 s | 236.57 s | 225.47 s |

总计 **95,095 Token**（输入 72,959，输出 22,136），上游模型时间 613.33 秒，
CLI 时间 649.69 秒。修改后策略的保留阶段实际 Token 多约 14.4%，因此相同预算
上限不等于相同实际开销。不估算缺少账单依据的金额。逐次成本见
[costs.json](results/meta/costs.json)，每次源代码、Diff、请求、结构化输出和 CLI
事件位于 `results/meta/c0` 至 `c5`。`source.diff` 的基线是该请求的初始生成器源代码，
其目标路径表示候选接口；不要把 fixture 的 Diff 直接应用到冻结的生成器文件。

五个提案通过静态审计（包括一次元策略提案），一个被拒。通过审计后的程序才进入
动态环境；执行结束后由外部原 Verifier/BFS/PyBullet 评分。元策略请求和模型请求
共 16 个文件已按结构化值检查，未包含任何私有 val 包；没有发布 val 逐场景数据。
静态通过、受限运行通过、得分增加、元级能力证据在本实验中分别记录。

## 隔离与实际资产

复用已有 Apptainer + seccomp 单进程执行器；候选和元策略都不在宿主执行。
无宿主 Home/凭据、外部网络、GPU；内核禁止文件打开、进程/线程创建与提升资源
上限。256 MiB 地址空间、5 秒 CPU、30 秒进程存活、1 MiB 总标准输出限制。
静态审计不是安全隔离证明。八项实时恶意行为回归全部通过；全套测试 176 项通过。
CPU/内存限制适用于这一禁止创建进程和线程的窄接口，不宣称服务器已委派 cgroup。

按预登记的 open/slalom 首张可行地图各选前后两个场景，共四场景、12 张真实
Blender 4.2.0 CUDA/A100 图片，均有 `.blend`、`.glb`。重新打开文件并重新导入
GLB，已核对资产包围盒、材质、灯光和三个相机。图像没有参与几何/可解性评分。
见 [渲染对照](renders/comparison.jpg) 与 [渲染记录](renders/summary.json)。

与真实调用实验一致，时间字段不要求一致。证据见 [checks/replay.json](results/checks/replay.json)。

几何/解与代码提案均可按保存的源代码、种子和条件重放；模型再次采样不保证产生
相同代码，耗时也不要求完全一致。原始本轮运行保存在服务器的
`/srv/lab-disks/disk2/users/xymo/rsi/generalization_meta_run`；私有 val 逐项数据留在这里，
公开归档只包含 val 汇总，模型请求中没有 val 数据、存在性见证或 task A 成绩。

这实现了可自动改写的元策略程序和最小配对评估。一次元级程序修订，即使有正向
指标，也不能证明持续、递归或开放式 RSI；没有修改底层模型，也没有开放控制器
或可信评价机制的自修改。
