# M2 失败归因：单布局改进与生成分布约束不等价

从 `46d87dc` 开始，只做公开开发集机制消融和真实执行路径审查。**没有新 Codex 算法/元策略提案调用，没有生成 M3，没有改阈值或部署消融版本。**

本轮支持三个具体判断：重采样是当前实现保留位置变化的重要来源；最终 minimum-loss 相较同轨迹的 last-valid 选择了更集中的位置分布；随机初始朝向提高了旋转变化，但在部分 dev 输出降低可见性。尚不能把跨划分的退化单独归因于一个机制，也没有证实元级能力提升。

## 1. 实验边界与复现核对

协议见 [PROTOCOL.md](PROTOCOL.md)。固定原 pilot 的 **8 个公开 dev 条件 × 原有两个种子**，没有读取或运行私有验证/终测任务，也不使用终测反馈选择参数。七组共 **112 次隔离生成、2,688 次生成查询**；每次严格 24 查询。另在 full 的固定轨迹上做两种最终筛选重评分，共 32 次；这些不是新提案或额外生成查询。全部 112 个常规最终输出及 32 个筛选输出都经过原独立 MeshWorld 的最终物理/通行检查。

原始 group-restart 与 full 的 32 个重跑输出状态逐项等于旧记录，质量/硬结果复现。每组的实际 source 位于 `results/<组>/payload/layout.py`，静态审计、干预 diff、逐 seed 状态/轨迹/执行资源和汇总一起保留。冻结策略、历史候选、任务、资产、Verifier、MeshWorld、预算和执行器均未修改。

消融中关闭投影或重采样采用“执行影子计算但丢弃输出”，尽量保留随机消耗；不重分配空出查询。减为一轮投影会改变后续随机调用路径。这些比较是固定程序机制的干预，不能代表在同预算重新设计后的最优无该机制算法，更不能当删算后的加速结果。

相对原始生成器，full 的位置保留仅 **71.74%**，可见性下降 **1.8011 个百分点**，dev 已违反原多目标条件，问题并非只在终测出现。所有消融/筛选版本也都未同时通过原 `eligible` 的 dev 门槛；没有选择“看起来最好”的消融版本部署。基线与自身相比不满足“误差改善 .01m”，不把它的自比较当作失败候选。

完整数值、每条件指标、配对变化、交互、原验收结果见 [analysis.json](results/analysis.json)。

## 3. 能归因到什么程度

下列区间为 8 个条件聚类的描述性 95% bootstrap，差值为“干预 − full”；不作多重显著性筛选，不把两种子距离当成 16 个独立分布样本。

**随机初始朝向不是位置塌缩的单一原因。** 去掉它后，旋转多样性下降 31.97°（区间 −59.47 至 −5.18），位置从 .43510 降到 .37989m，偏好误差只增加 .00148m（−.00029 至 .00474）。可见比例增加 .8415 个百分点（区间 0 至 2.0605），收益集中在条件 2/6 的三次运行。两次运行中两个可见物体位置都不变、姿态改变，可见像素比例改善；另一次位置也改变，不能纯归为姿态。详见 [visibility_observations.json](visibility_observations.json)。这支持 dev 的姿态/可见性权衡，不能据此认定已解释原终测的全部 1.28 点损失。

**关系投影主要解释偏好质量，不足以单独解释集中或遮挡。** 去投影误差增加 .36970m（.19499 至 .57426）；位置多样性增加 .08342m，但区间 **−.05114 至 .23896** 包含零，可见性逐运行完全不变。把六轮缩为一轮没有恢复多样性，反而降到 .38523m，并有一次通行失败。因此不支持“投影次数越多必然越集中/越遮挡”。full 的 floor 更新相对上一重采样最大 1.498m；限制单次 .25 的内部步长不等于累计位移受同一上限约束。

**重采样在这份算法中显著维持位置变化。** 去掉它的位置多样性只剩 .03249m，相对 full 下降 .40261m（−.52180 至 −.29962），旋转仍为 103.65°。随机初始 yaw 可以保留旋转变化，却不能替代位置分布。该干预保留了固定的初始化/投影/选优路径；不证明所有无重采样方法都会塌缩。

**最终单场景选优存在可观测的分布权衡。** 固定 full 的全部自适应提案不变，最后 query-valid 的位置多样性比 minimum-loss 提高 .15883m（.04494 至 .26997），但误差恶化 .58096m（.37359 至 .82171），可见性不变。选首个有效状态的位置多样性为零，说明“去掉 minimum-loss 就能恢复分布”也不成立。反事实只替换最终索引，未改变搜索中使用 minimum-loss incumbent 的逻辑；后者的贡献仍未分离。

full 平均提案位置多样性为 .56799m，最终 .43510m；原初始程序分别为 .63373/.60647m。14/16 个 full 最终状态来自投影查询。搜索路径与最终选择都参与分布变化，但二者不是可线性相加的独立贡献。

**交互不可忽略。** 预定 yaw×投影 2×2 的差中差为位置 +.05963m（.01259 至 .12513）、旋转 +25.13°（6.86 至 50.25）。可见性交互为零。由于投影保持 yaw 不变，旋转统计变化也可能通过重采样/最终索引选择产生，不能解释成投影直接旋转物体。

## 4. 多目标失配与元路径证据

原 optimizer_loss 对每个布局使用碰撞、越界、支撑、关系、偏好及可见性项，**没有跨种子位置/旋转分布约束，也不等同于外部 eligible**。本 dev 中原始→full 的偏好项收益约 `.3 × .185186 = .05556`，可见性损失的 scalar 代价约 `2 × .018011 = .03602`；其他项几乎相同，平均 loss 从 .27579 降到 .25625。单布局目标确实改善，却同时违反外部位置和可见性门槛。这是实际测量可见的目标不等价，不能靠“优化 loss 更充分”保证全部研究要求。

[执行路径审查](EXECUTION_PATH.md) 给出逐函数和真实日志证据：

- 新诊断真实执行，但把旧四候选 .7382/.5429 的位置/旋转保持率用于当前“已测瓶颈”，取 rotation 优先；当前初始程序没有相应保持率对照。
- M1 dense→M2 barriers 改变了 probe 子集均值，但最终交给后端的逐项场景仍是同一 8 条，只有顺序变化，新 probe 例子被丢弃。
- M2 程序自身不读当前算法 source，只看统计/例子；完整旧失败记录在其决策后才给后端。后端真实日志随后选择随机初始 yaw + 交替精修/重启。不能把后端分析全部算作 M2 程序的诊断能力。
- 旧推箱子术语残留，但可信连续任务合约和后端理解正确；尚无证据将其单独归因为退化。

因此合理根因是：历史风险与当前证据未分开，probe→反馈交付未闭合，单布局改进机制缺少对输出分布及全部裕度的实测闭环。开发消融支持部分局部因果关系；本轮不重新使用终测，**不能确定验证位置退化与终测可见性退化各由哪个单一机制主导**。只有两个种子的多样性估计也限制了跨条件结论，不能据此改原门槛。

## 5. 新方法与下一轮

[METHOD.md](METHOD.md) 给出最小的 Multi-Objective-Aware Meta-Improvement：current/history/constraints 分域、带来源的 observed/hypothesis 诊断、完整种子组的 probe 交付，以及依据实际候选裕度改变研究决策。保留原所有门槛和公共“任务→patch”边界，拟议接口改动尚未写入冻结策略。

下一轮只允许 M2 通过一次固定后端编辑产生 M3，先通过数据依赖资格检查，再在新初始程序/新私有条件、共同四种子和 K=1 下比较。包含创建最多五个编码任务，预定失败/天花板停止规则；本轮不执行。即使程序变动成立，也须独立多目标结果才能谈元能力改善，单个模型抽样仍不够证明持续 RSI。
