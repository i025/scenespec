# 建议：证据分域的多目标元级改进

这是下一轮的可实现设计，**本轮未实现或执行 M3**。冻结 M0/M1/M2、评价规则和外部预算均不变。方法针对已观察到的诊断分域、反馈交付和分布评价问题，不预先指定一个必须采用的生成器修复算法。

## 最小程序机制

1. **分开事实与风险先验。** 在现有策略 packet 的 summary 中使用 `current`、`history`、`constraints` 三个语义域。current 包含当前初始生成器的真实 dev 测量及已有的成对比较；history 是旧候选的机制/结果和不确定性；constraints 由可信控制器提供原门槛。每项数值只属于一个域，不递归合并成无来源的 risks。没有当前 baseline/candidate 比较，就输出“保持率未知，需要检验”，不能因旧候选低保持率而输出“当前已退化”。
2. **诊断返回结构化决策。** 元策略在既有 choose/propose 结果中附一个最小 `diagnosis`：`objective`、`status`（observed/hypothesis/unknown）、`evidence`（输入字段路径与条件/种子）、`probe`、`expected_observation`。程序先检查当前运行和硬失败，再检查当前成对约束；缺少当前对照时用历史作为待检验风险。后端任务文字由此决策和完整约束生成，不靠添加更长的固定提醒。
3. **确保 probe 证据真正交付。** 示例选择按条件选择完整多种子组，保留至少一个所选 probe 的完整组；同预算内在共同组与探测组间分配名额。记录 available/selected/delivered 的 condition_index、repeat，并比较集合，而不是把顺序变化算作新信息。若预算没有足够证据，明确写出缺口，不能把选 probe 本身当作实验已证实假说。
4. **区分单布局目标和输出分布。** 改进前给后端全部固定门槛以及当前已知裕度；候选运行后，从同任务多种子的配对记录重新计算裕度。分别记录每步提案与最终选优的分布、累计位移、visibility 与偏好变化。诊断必须根据本候选的实测违反项改变下一次研究目标或 probe；不能永远以历史旋转缺口为首要目标。有限 K 没有下一次机会时只记录失败，不隐式追加调用。

原本的公共边界仍是“Meta-Agent 提出改进任务，Coding Backend 返回 patch”。只建议扩展现有 summary 和决策中的诊断数据，复用 objective/analysis/strategy/feedback/allowed_files/budget，不引入新事件协议、版本字段、执行框架或模型。

## 保留原多目标门槛

| 约束 | 候选裕度（非负表示满足） |
|---|---|
| 无运行错误 | runtime_errors = 0 |
| 硬成功数不下降 | candidate.successes − baseline.successes |
| 平均可见比例损失不超过 .01 | candidate.visibility − baseline.visibility + .01 |
| 全配对位置保持至少 90% | candidate.position − .9 × baseline.position |
| 合法配对位置保持至少 90% | candidate.valid_position − .9 × baseline.valid_position |
| 旋转保持至少 80% | candidate.rotation − .8 × baseline.rotation |
| 合法配对数不下降 | candidate.valid_pair_count − baseline.valid_pair_count |
| 偏好误差改善至少 .01m | baseline.preference − candidate.preference − .01 |

这些是原 `eligible` 的解释，不是新评分器。改动前只有初始程序测量时，不能填造候选裕度。合法配对集合变化必须同时报告全配对和共同合法任务子集，后者仅用于分析，不能取代原门槛。任务级配对区间表达不确定性，不事后改变平均值验收规则。

## 下一轮 M2 → M3 最小验证

1. 仅用本轮 **dev 消融与路径证据** 建立父代输入。旧 val/test、其逐项反馈以及合法参考场景不输入策略编辑。让固定 M2 通过现有原生 Codex 后端提出一次自身程序修改，只允许修改诊断、研究目标组织、probe/示例选择。可信控制器仍固定。研究者预先给出上述方法方向，因此后续应称“给定研究方向的自动元策略修订”，不能声称父代自主发现了全部方法。
2. 隔离资格检查验证真实数据依赖：仅替换历史保持率时不能改变当前 observed 瓶颈；替换当前成对违反项必须改变诊断及可检验研究决策；已选 probe 的配对证据必须进入最终任务；文本变化或顺序变化本身不算通过。拒绝后停止，不手工修补 M3。
3. 冻结 M3 后再生成新条件。预先冻结两个新的初始算法实现，缺陷不同，避免只对本轮 M2 候选做模板修补；先以原评分检查任务可行性和非天花板，不能根据 M2/M3 成绩重选。共同使用同一 Mesh Benchmark 范围，不新增场景类型。
4. 每初始程序固定 dev 6 条件、选择集 6 条件、最终私有集 12 条件，每条件 **4 个共享算法种子**。复用现有逐 case 执行；统计扩为全种子对的平均原 distance，再对条件平均，合法配对亦按原含义统计。这样改变了多样性估计的样本数，必须预先登记为下一轮共同测量设计，不能与旧双种子数值直接混算，也不能调整 .90/.80 门槛。每次生成仍 24 查询。固定一次模型调用任务的模型、工具、请求/Token/时间上限和全部场景运行预算，两策略完全相同；基线成本也计入总账。
5. 先在第一个初始程序上做 M2/M3 各一次 K=1（两次下游编码）。若两者都没有完整有效的多目标改进，或两者都已近天花板，停止并报告；否则执行预登记的第二个初始程序（再两次），不以 M3 是否领先决定续跑。含 M3 创建最多 **5 个编码任务**；服务请求数另记，不能把原生编辑中的多次请求算成一次服务调用。
6. 主要比较独立选择下的接受率/MetaImp@1，同时报告原始候选与最终回退版本的全部质量、分布、硬成功和成本。先封闭选择，再运行私有终测；终测不能回流诊断或补选。固定预算下，只有原门槛全通过的候选才用偏好误差作次级排序，不能以更低单场景 scalar loss 代替外部多目标验收。

每策略每初始程序只有一次模型抽样，即使两个任务都改善，也只构成小规模可行性证据。若要声称稳定元能力优势，需要之后另行预登记独立模型配对重复，报告离散程度和失败率；不能把同一生成程序的多种子布局区间当成元策略抽样置信区间。元策略代码改变、证据驱动决策生效、独立多目标能力提升是三个不同验收层次。
