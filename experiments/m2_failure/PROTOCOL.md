# One M1-directed M2 edit and one independent three-arm pilot

Base 526a309. Freeze this protocol, old-dev analysis, new initializer and controller
before any inference. No changes to M0/M1, Mesh tasks/assets/scorer, original
eligible, coding backend or BUDGET. No hashes/custom versions/extra agents/GPU.

Stage 1 uses ONLY the published dev records of the four prior attempts. Reconstruct
saved trace values with trusted state transforms, verify final min-optimizer states,
compare raw proposal/rolling-incumbent/final seed-pair diversity, projection-slot
statistics and alternative selectors on the SAME recorded query stream. No model,
candidate execution, Mesh query or fresh scenario. Selector replays have query-only
validity: unchosen states have no independent gravity/navigation acceptance. The
adaptive proposal stream depends on the incumbent; these are not causal ablations.
The external multiobjective candidate gate rejected all prior programs and did not
install their diversity loss. Distinguish it from generator-internal best-index logic.

Stage 2 reserves ONE M2 edit and at most THREE future generator edits before inference.
Execute original M1's choose/propose in unchanged LayoutProcess on old dev attempt
summaries and its own source. Feed its actual analysis/instructions, selected old-dev
statistics and parent source to the unchanged native Codex backend. The fixed outer
contract authorizes META-POLICY editing; parent's old downstream generator-only
wording is retained as historical data, not permission to change other files.
No manually written generator repair recipe, previous candidate source, references,
selection/test feedback, future initial generator or future task is mounted.
M1 does not independently decide whether/when to self-modify: the controller invokes
this authorized phase. This is program-level revision, not model-weight modification.

Only algorithm.py (a clone of M1) is editable. Preserve choose/propose schemas and
probe menu. Program changes must affect data-dependent experiment choice/example
membership, not just analysis/prompt text. Original policy AST audit and isolated
execution on four fixed public-schema synthetic diagnostic scenarios (choose and
propose each) validate bounds, nontext change relative to M1 and adaptive decisions.
They are interface qualification, not capability scoring or hidden world tests.
One failed patch/qualification stops the live pilot. No manual repair or retry.
Save raw code, diff, Git versions, JSONL, usage, parent decisions and all failures.
Freeze qualified M2 in Git BEFORE new conditions or generator feedback are created.

Stage 3 is ONE feasibility pilot: M0/M1/M2 each optimize the SAME NEW group-restart
initializer, K=1, one independent coding sample per arm. This initializer resets an
entire support group (including both floor objects) instead of Repair's single-object
resampling. It is registered now, never shown during M2 creation or tuned after
results. Generate 8 fresh dev, 8 private selection and 12 private test conditions
using the unchanged distribution, two shared algorithm seeds, verify all references.
No reuse of old task packets. Stop without pilot inference if initial dev runtime
errors exist, hard rate<.5, preference error<.02m or position diversity<=.05m; no tuning
or resampling to pass. No second initial generator/repetition this round, regardless
of results. One initializer cannot establish transfer across initial-generator families.

Use the original probes/common pool and exact validate_decision. The common adapter
adds current cross-seed pair metrics, aggregate multiobjective dev metrics, and the
SAME historical dev failure statistics to ALL three policies/backends. This is an
explicit shared information change from the old study; within-pilot comparisons are
fair, but cross-study differences cannot be attributed only to M2. Same 16 measured
initial dev outputs for all arms, bounded selected examples as before. No M2-only
evidence or extra query tool. R&D agent cannot access trusted evaluator/hidden data.

Per coding task unchanged paired-repair BUDGET: gpt-6.1-sol medium, CLI 0.163.0,
600s, <=6 upstream requests, <=4096 output tokens/request, 1MiB cumulative request
bytes, 196608 bytes/request and 400000 total service tokens with the existing
conservative reservation. Unknown/exceeded usage fails. Same restricted tools.
At most two concurrent editors, serial scene evaluation. Each scene exactly 24
Mesh/pixel queries, old LayoutProcess CPU/memory/PID/time/output limits, external
independent MeshWorld. No host subprocess execution fallback for generated Python.
M2 creation cost is separate from equal per-arm generator optimization budgets.

Reserve all THREE K=1 arms before inference. Original eligible on private selection
only: hard count cannot fall, visibility loss<=.01, all/valid pair position>=90%,
rotation>=80%, no lower valid-pair count, >=.01m preference improvement, no errors.
No new weights/thresholds/dev veto. Reject => initial source selected. Close all
proposals and selection decisions before test. Report raw candidates and selected
versions on new test; never reselect from test. No extra calls after failure.

Separate: M2 program/decision modification; complete/static/runnable candidate rates;
hard success, preference, position/rotation and valid-pair diversity, accept rates;
per-arm costs and one-off self-edit costs; selected vs raw comparisons. Task-cluster
intervals are not independent model sampling. N=1 per arm/one initializer is feasibility
only, even if positive. Do not claim proven recursive capability from code mutation.
Private selection/test packets, seeds, references and per-item states stay outside Git.
